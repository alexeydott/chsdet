# Tests

This directory contains the DUnitX unit tests and the reproducible corpus used to validate `chsdet`.

## Layout

- `ChsDet.Tests.pas`: main DUnitX fixture for wrapper behavior and selected encoding regressions
- `ChsDet.Corpus.pas`: helper for loading corpus cases and building benchmark results
- `corpus/manifest.tsv`: source of truth for corpus expectations
- `corpus/data/`: generated byte fixtures consumed by tests and the benchmark
- `corpus/generate-fixtures.ps1`: regenerates `corpus/data`
- `corpus/MATRIX.md`: latest corpus benchmark matrix

## Corpus Workflow

Regenerate fixtures after changing `corpus/generate-fixtures.ps1`:

```powershell
powershell -ExecutionPolicy Bypass -File tests\corpus\generate-fixtures.ps1
```

Rebuild and run the corpus benchmark:

```powershell
cmd /d /s /c '"D:\Embarcadero RAD Studio\23.0\bin\rsvars.bat" && dcc64 -B -Ebin64 -N0bin64 -Itests ChsDetCorpusBench.dpr && bin64\ChsDetCorpusBench.exe'
```

The benchmark rewrites `corpus/MATRIX.md`. Strict rows are enforced by `CorpusStrictBenchmarkPasses`; informational rows are tracked for visibility only.

## Legacy Single-Byte Coverage

`corpus/data/cp437-nfo-art.txt` is generated from NFO-style pseudo-graphics encoded as code page 437. It protects the DOS/OEM art heuristic and should detect as:

- Name: `IBM437`
- Code page: `437`
- Language: `DOS`

`corpus/data/cp437-plain-no-art.txt` is generated as a negative regression fixture. It is encoded as CP437 but intentionally has no box/block drawing bytes, and the test suite verifies that it is not reported as `IBM437`.

`corpus/data/cp437-small-nfo-art.txt` covers a smaller mixed text/art NFO sample. The CJK corpus fixtures are also checked explicitly so multibyte legacy text does not false-positive as `IBM437`.

Additional generated fixtures cover `IBM850`, `IBM852`, `IBM858`, `windows-1250`, and `KOI8-U`. The related unit tests use corpus fixtures rather than ad hoc sample files.

`DisableCodePage` is covered for the heuristic-only paths as well: CP437 pseudo-graphics, OEM text signatures, `windows-1250`, and `KOI8-U` must not be reported after their code page has been disabled.

Multibyte regression coverage uses generated mixed ASCII/script samples that preserve the key characteristic from real files: structured multibyte sequences contain bytes that also look like legacy single-byte signatures when counted individually. DUnitX covers DBCS samples for `GBK`, `Big5`, `Shift_JIS`, `EUC-JP`, and `EUC-KR`, plus UTF-8 and UTF-16 LE/BE without BOM. These samples must report their structural encodings instead of `IBM437`, `IBM850`, `IBM852`, `IBM858`, `windows-1250`, or `KOI8-U`.

The generated DBCS overlap fixtures are named `legacy-overlap-*.txt` in `corpus/data/`.

## PR #1 range/overflow regression gate

`ChsDetTests.dpr` explicitly links `tests/ChsDet.Tests.pas` and
`tests/ChsDet.TableTests.pas`; the similarly named file at repository root is
not the runner's fixture. DUnitX must already be available in the Delphi paths.

From a RAD Studio command environment, run PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run-range-matrix.ps1
```

The first script rebuilds with `-B` into isolated DCU/output directories for
Win32 and Win64, with all four R/Q combinations. It runs the full existing suite,
checks the NUnit XML for discovered table tests and non-passing cases, and
compares exact snapshots across directive modes within each platform. It does
not assume identical floating-point bits between Win32 and Win64.

The historical `compare-pr1-baseline.ps1` helper was written for PR #1 at
revision `100f39d`. It is **not a gate for the current detection changes**:
its snapshot-equality requirement and copied harness refer to that historical
review. Run it only in the historical checkout. It uses an isolated temporary git worktree at main commit
`4660893fb7966f78982ef23fb2fb92215499cbec`. It copies the **same test harness and
corpus** there, leaves production code from main intact, compares R-/Q-
snapshots, and requires runtime range failures in the three deterministic raw
memory tests under R+/Q+. A compilation failure does not count as reproduction.
Logs and XML remain under ignored `build-range/`. The script removes only its
own uniquely named temporary worktree.

The literal ESC fixtures extend the strict manifest from 36 to 39 cases. Their
bytes are written directly by `generate-fixtures.ps1`, without a code-page
encoder. `EscProberPreservesDesignatorsAtEverySplitAndAfterReset` deliberately
tests the ESC prober directly; it does not assert every split works through the
universal wrapper (see `PR1-REVIEW.md` for the existing HZ prefix issue).

`RawTablesDoNotRequireDynamicArrayHeaders`,
`PackedNibblesIncludeHighBitAndWordBoundary`, and
`DistributionChecksActualLengthBeforeReading` place a zero 8-byte sentinel
immediately before raw payloads. This supplies zero in the location incorrectly
read as dynamic-array length on either architecture, making old-code failures
independent of linker placement. No unexpected exception is swallowed.

A compiler-independent audit of literal tables can also be run:

```sh
python tests/audit-tables.py
```

This parses only the repository's literal table syntax, traverses the reachable
state graph for every byte and checks frequency initializer counts. It does not
compile or execute Delphi and cannot establish a runtime PASS.

## October 2026 recognition regressions

The runner also links three new fixtures with explicit registration:

- `ChsDet.RegressionTests.pas`: 12 public API / Unicode / mapping scenarios.
- `ChsDet.ProberTests.pas`: 12 low-level model, state, confidence and memory-boundary scenarios, including rejection of a stale Shift_JIS winner, exact summary joins and 64-bit sequence counters.
- `ChsDet.StreamingTests.pas`: 11 word/tag boundary, mixed ASCII/non-ASCII word, bounded-prefix memory and chunked corpus scenarios.

The range matrix requires at least 12/12/11 tests in these fixtures, rejects empty
execution and retains the original raw-table checks. The Japanese-context
memory-boundary test uses Windows `VirtualAlloc` / `VirtualProtect` guard pages.
It checks a meaningful postcondition after the protected single-byte read;
an unexpected access violation is not swallowed.

The current native Delphi 12 matrix executes 89 tests per configuration on
Win32 and Win64 with all four R/Q combinations. All 89 pass with no ignored
tests, failures or errors; recognition snapshots match across R/Q modes within
each platform. These native results are separate from the historical Free Pascal
evidence linked below.

The bounded-prefix regression streams 2 MiB of delimiter-free ASCII in reused
4 KiB blocks and checks live allocated memory after warm-up (64 KiB tolerance).
It fails on the previous byte-buffer implementation. Sequence-summary tests
compare exact character, frequency, bigram-category and boundary counters with
literal-byte feeding in both normal and reversed models. A seeded repeated-letter
case checks accumulation and commit beyond `2^32` without a multi-gigabyte test.

See [the review](review-2026-10-24/REPORT.ru.md),
[actual supplementary execution evidence](review-2026-10-24/SUMMARY.md), and
[portable runner instructions](portable/README.md). No Delphi execution result
is implied by the Free Pascal reports.
